polish-website

A vibecoded app usually runs. It can also serve its database to anyone holding the public key, and the owner tends to find out last.

This agent skill audits an AI-built site or app before launch, across security, legal, design and copy, and App Store and Google Play readiness. Two scripts gather the evidence, read-only agents confirm it, and every fix comes with the command that proves it worked.

1

Exhibit A: two findings

Every finding, from the scripts and from the agents, has the same six lines. It names the place, quotes the proof with secrets redacted, and ends with the command that shows the fix worked. These two come from a made-up app.

Severity comes from a fixed table, not from how alarming a finding sounds:

LevelMeans
P0exploitable now by an anonymous visitor, or a certain store rejection
P1exploitable by a signed-in user, a legal duty with a per-incident penalty, or a likely store rejection
P2hardening, or a legal or store item that depends on a fact the owner must confirm
P3an AI tell, polish, or anything cosmetic

The owner is AGENT when a code change fixes it, and HUMAN when it needs a dashboard, a store console, a lawyer, a key rotation, or content only you know.

3

Two ideas

An agent handed a checklist reads it, greps for a few items, and reports "RLS enabled." So this skill runs on two ideas.

Evidence before opinion

Every finding carries the line or command output that proves it, and the command that proves it's fixed. The scripts run first, so the mechanical checks happen the same way every time. Each script finding must come back from an auditor confirmed or dismissed, and triage drops any finding without evidence.

Blind reviewers see what the public sees

A reviewer who has read the code knows what the app means to do. Attackers, regulators, store reviewers, and visitors see only what it does. So the stranger never sees the repo, and the attacker gets a URL and two test accounts.

Seven phases

PhaseWhatAgents
0Map the app and its triggersnone
1Scan: scripts, then stack toolsnone
2Audit, read-only, in parallel3–6
3Triage and report; the user approves fixesnone
4Fix by file ownership, in waves1/cluster
5Verify: rerun, attack, fresh stranger2
6Handoff checklistnone

Nothing in your code changes before you have seen the P0 and P1 list. If Phase 1 turns up a live key, you hear about it right away, with the key to rotate and where, not in the report.

Launch gate

  • Zero open P0. Every P1 is fixed, or you accepted it in the report in your own words.
  • The attack pass returns PASS or N/A for A1 through A10, each with the request and response.
  • A fresh stranger finds no P0 or P1, and no claim you can't back.
  • Native apps: on a fresh iPhone, iPad, and Android install, sign up, finish the core flow, buy, restore, and delete the account.
5

What it checks

Security

Keys behind public env prefixes. Secrets in bundles and git history. Tables with no RLS, or RLS that lets everyone in. Users who can raise their own credits or role. Public buckets, unverified Stripe webhooks, SQL built from strings, open CORS, exposed .env and .git files, and missing headers. On your own Supabase project, what the anon key can actually read.

Legal

Fonts loaded from Google's servers, and trackers or session replay that start before consent. Missing privacy and terms pages. Pre-checked consent boxes. Accounts with no way to delete them. Missing alt text, lang, and focus styles. Social proof nobody can check.

AI tells

Purple-to-blue gradients, gradient text, glass cards, three icon boxes in a row, emoji as icons, Inter everywhere, every section fading in on scroll, em dashes and stock buzzwords, placeholder people, and tab titles like "Vite + React." One on its own is a style. Five together is the finding.

App stores

Capacitor apps that only wrap a website, in-app account deletion, Sign in with Apple parity, store billing and restore, the Android target SDK floor, sensitive permissions, iOS privacy manifests, and permission prompts that don't say why.

Install

With the Skills CLI:

shell
npx skills add jgoetzmann/polish-website --global

Leave off --global to install into the current project only.

Claude Code 2.1.142 or newer can install it as a plugin:

Claude Code
/plugin marketplace add jgoetzmann/polish-website
/plugin install polish-website@polish-website

The plugin command is /polish-website:polish-website. Or ask in plain words: "Is my Lovable app safe to launch?" or "Will Apple reject this Capacitor app?"

The two scripts also run on their own, with no agent. They need Python 3.9 or newer and nothing else:

shell
python3 scripts/scan.py path/to/app
python3 scripts/probe.py https://staging.example.app
python3 scripts/scan.py . --fail-on P1

The last line is a CI gate: it exits 1 on any P0 or P1.

7

When not to use it

  • On anything you don't own. The live checks and the attack pass run only against targets the owner confirms, staging first.
  • As the only review of a system that moves money, holds health records, or has a team of engineers. Run it, then get a professional pentest and a lawyer.
  • As legal advice. It is a starting point that tells you what to ask a lawyer.
